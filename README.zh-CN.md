大多数 AI 智能体依赖的是嵌入向量,而不是语义:只有相似度分数,没有结构、没有关系,也无法解释为什么会返回某个结果。

Semantica 是位于你的 LLM、向量库和智能体框架之下的语义/上下文层:它是确定性的基础设施(图构建、推理和溯源都不需要 LLM;即使用到 LLM 也是可选且与厂商无关的,通过 `semantica.llms` 支持所有主流供应商,包括 OpenAI、Anthropic、Gemini 等),能把零散的企业数据转化为结构化、可查询的上下文图和知识图谱,承载的是业务上下文,而不仅仅是数据结构。本体与受控词表(OWL、SHACL、SKOS)让一个实体对你的业务*意味着什么*(它的定义、关系和规则)像数据本身一样显式,而不只是一个嵌入向量。

决策溯源和审计轨迹并不是产品本身,它们是这套结构的自然产物。在监管机构可能追问的领域里,让你的智能体更聪明的这套结构,同时也能让你对"为什么"给出直截了当的回答。

> [!NOTE]
> **系统层面的可解释性,而非基础模型层面的可解释性。** Semantica 不会暴露或重建 LLM *内部*发生了什么:与任何外部系统一样,它的内部推理依然是不透明的。Semantica 解释的是模型*之外*的部分:输入的上下文、产出的决策、其溯源、相关关系、所应用的策略,以及完整的执行轨迹。

**适用人群:**

- **AI/ML 平台团队**:交付会做出重要决策的智能体,需要结构化、可查询的上下文,而不仅仅是一个向量索引
- **使用 Databricks、Snowflake 或 SAP 的企业数据团队**:把湖仓或数据仓库中已有的表转化为受治理、带血缘追踪的知识图谱,无需导出到第三方 SaaS
- **合规、风控和审计团队**:需要以监管机构认可的格式,直接回答"AI 为什么这么做?"
- **受监管的企业**(金融、医疗、法律、政府、国防):既不能交付黑盒,也不能把数据交给别人的 SaaS 去获得黑盒
- **平台与基础设施工程师**:希望知识图谱、推理和溯源栈可自托管、可替换,不被某一家厂商的后端锁定
- **数据与知识工程师**:基于杂乱的多源数据构建知识图谱,冲突事实会被标记、重复项会被合并,而不是被悄悄覆盖

<a id="what-semantica-gives-you"></a>
## Semantica 能为你提供什么

- **上下文图(Context Graphs):** 一个结构化、可查询的图,涵盖你的智能体所知道的、所决定的和所推理的一切
- **决策智能(Decision Intelligence):** 每个决策都是一等公民对象:可追溯、可按先例检索,并具备因果关联
- **AI 治理与本体:** SHACL 约束、冲突检测、合规规则、OWL 生成和 SKOS 词表,全部配有可视化编辑器
- **完整可审计性:** 每个事实都带有 W3C PROV-O 溯源,可导出为 JSON、CSV 或 RDF
- **确定性推理:** 前向链、Rete 网络、Datalog 和 SPARQL,推理路径完全可解释,而非黑盒
- **知识管线:** 多源接入、实体感知分块、NER/关系/事件抽取以及图构建,内置语义去重和保留溯源的合并
- **企业数据平台:** 为 Databricks(Unity Catalog + Delta Lake)、Snowflake 和 SAP OData 提供原生连接器,湖仓或数据仓库中已有的数据可直接变成带溯源的图节点,无需导出/导入这一跳
- **图分析:** 在你刚构建的图上进行中心性、社区发现、链接预测和最短路径查询
- **多模图存储:** 支持 RDF(Oxigraph、Blazegraph、Jena、RDF4J)和标签属性图(Neo4j、FalkorDB、AGE、Neptune),以及向量库,切换时无需改动代码
- **可视化:** 在交互式浏览器工作台中探索任意图、本体或时间线
- **开箱即用的集成:** 支持 Agno、CrewAI 和 LangChain,提供完整的 MCP 服务器、CLI、REST API,以及覆盖主流编辑器的插件

<a id="quick-start"></a>
## 快速开始

```bash
pip install semantica
```

```python
from semantica.context import ContextGraph

graph = ContextGraph(advanced_analytics=True)

# 每个智能体决策都会成为可查询、可审计的知识节点
decision_id = graph.record_decision(
    category="vendor_selection",
    scenario="为 HIPAA 工作负载选择云服务商",
    reasoning="AWS 提供 BAA、成熟的 HIPAA 工具链,且团队已有相关经验",
    outcome="selected_aws",
    confidence=0.93,
)

# 询问"这是怎么发生的?",得到真实、结构化的答案
chain     = graph.trace_decision_chain(decision_id)       # 完整的因果谱系
similar   = graph.find_similar_decisions("cloud vendor", max_results=5)  # 先例
impact    = graph.analyze_decision_impact(decision_id)    # 下游影响图

# 策略闸门:依据默认规则检查你传入的字段
# (confidence >= 0.7,outcome 属于 approved/rejected/flagged,且设置了 decision_maker)
compliant = graph.check_decision_rules({
    "category": "vendor_selection",
    "outcome": "approved",
    "confidence": 0.93,
    "decision_maker": "platform-team",
})  # {'compliant': True, 'violations': [], ...}
```

<a id="architecture"></a>
## 架构

Semantica 是一条真正的端到端管线,而不是一个只有营销名头的单一库。下面的每个阶段都是已发布的模块,均可独立导入:

```
来源 → 接入 → 解析 → 规范化 → 切分 → 抽取 → 冲突检测 → 去重
   → 知识图谱 → [ 本体 · 推理 · 溯源 · 决策 ] → 增强后的知识图谱
   → 向量库 + 多模图存储(RDF 与 LPG) → 导出 / 可视化 / REST · MCP · CLI
```

- **接入(Ingest):** 文件、网页、数据库、企业数据平台(Databricks、Snowflake、SAP)、云(Google Drive、Elasticsearch)、流(Kafka、Kinesis)、Git、邮件、MCP
- **解析 → 规范化 → 切分:** 文档解析、文本/实体/日期规范化、GraphRAG 原生的实体感知分块
- **抽取 → 冲突检测 → 去重:** NER、关系、事件、三元组;冲突事实在合并之前被标记并解决
- **知识图谱:** `GraphBuilder` 负责构建图;双时态事实和完整的图分析(中心性、社区、链接预测)都运行在其上
- **本体 · 推理 · 溯源 · 决策:** 位于知识图谱之上的智能层,包括 SHACL/OWL 治理、Rete/Datalog/SPARQL 推理、W3C PROV-O 血缘,以及一等公民的决策记录
- **存储:** 设计上即为多模,支持 RDF 三元组存储(内嵌 Oxigraph、Blazegraph、Apache Jena、Eclipse RDF4J)、标签属性图(Neo4j、FalkorDB、Apache AGE、AWS Neptune)和向量库,切换时无需改动代码
- **输出:** 导出(RDF、OWL、Parquet、Cypher、JSON-LD)、交互式可视化,以及通过 REST API、MCP 服务器或 CLI 访问

<a id="decision-intelligence"></a>
## 决策智能

决策智能把每一次 AI 选择从转瞬即逝的推断,变成永久、可审计、可查询的记录。它回答的是*"你的 AI 决定了什么、为什么这么决定、之后发生了什么?"*,这正是监管机构和企业风控团队越来越急切追问的问题。

在 Semantica 中,决策不是一行日志,而是拥有完整生命周期的一等公民图节点。在受监管领域,每一个 AI 决策都必须能追溯到来源,并能向审计方自证合理:`record_decision()` 会创建一条永久、结构化的记录,可导出为 W3C PROV-O,这是大多数合规框架接受的、用于向监管机构提交的格式。

```
record_decision()             → 以完整的结构化上下文存储为图节点
add_causal_relationship()     → 关联到上游原因和下游影响
find_similar_decisions()      → 在所有历史决策中进行语义先例检索
trace_decision_chain()        → 回溯到根因的完整因果谱系
analyze_decision_impact()     → 下游影响图 - 该决策影响到的一切
check_decision_rules()        → 针对可配置规则集的策略合规闸门
export / audit trail          → 导出 W3C PROV-O、CSV 或 JSON,用于向监管机构提交
```

```python
from semantica.context import ContextGraph

graph = ContextGraph(advanced_analytics=True)

# 以完整的结构化上下文记录决策
app_id = graph.record_decision(
    category="credit_application",
    scenario="个人贷款,年收入 $85k,负债收入比 31%,就业 3 年",
    reasoning="收入达标;就业稳定;无不良信用记录",
    outcome="proceed_to_underwriting",
    confidence=0.88,
    metadata={"applicant_id": "A-7291"},
)
uw_id = graph.record_decision(
    category="loan_underwriting",
    scenario="A-7291 的核保审查",
    reasoning="负债收入比符合政策;36 个月信用记录良好",
    outcome="approved",
    confidence=0.94,
)
rate_id = graph.record_decision(
    category="interest_rate",
    scenario="为已批准的贷款 A-7291 分配利率",
    outcome="rate_set_8.9pct",
    reasoning="基准利率 + 2.4%,依据风险等级 B2",
    confidence=0.99,
)

# 构建可审计的因果链 - relationship_type 必须是
# CAUSED、INFLUENCED 或 PRECEDENT_FOR 之一
graph.add_causal_relationship(app_id, uw_id,   relationship_type="CAUSED")
graph.add_causal_relationship(uw_id,  rate_id, relationship_type="INFLUENCED")

# 查询智能
chain     = graph.trace_decision_chain(rate_id)
similar   = graph.find_similar_decisions("personal loan approval, 31% DTI", max_results=5)
impact    = graph.analyze_decision_impact(uw_id)
compliant = graph.check_decision_rules({
    "category": "loan_underwriting",
    "outcome": "approved",
    "confidence": 0.94,
    "decision_maker": "underwriting_agent",
})
insights  = graph.get_decision_insights()
```

<a id="context-graphs"></a>
## 上下文图

上下文图是传统 RAG 所缺失的结构化记忆层。扁平的嵌入向量回答的是*"什么是相似的?"*,而上下文图回答的是*"什么是相连的、为什么相连、以及如何相连?"* 每个实体、关系、决策和事实都是一等公民节点,可通过图遍历进行查询。实体链接到源文档,决策链接到证据和后果,事实携带完整的溯源,冲突会被检测出来而不是被悄悄覆盖。

```python
from semantica.context import ContextGraph, AgentContext
from semantica.vector_store import VectorStore

graph = ContextGraph(advanced_analytics=True)

# 添加带类型属性的节点
graph.add_node("acme_corp",    "Organization", name="Acme Corp", industry="SaaS")
graph.add_node("alice_chen",   "Person",       name="Alice Chen", role="CTO")
graph.add_node("contract_001", "Contract",     value=2_400_000, currency="USD")

# 添加带类型、带权重的边(额外的关键字参数会成为边的元数据)
graph.add_edge("alice_chen", "acme_corp",    edge_type="works_for",  since="2019-03-01")
graph.add_edge("acme_corp",  "contract_001", edge_type="party_to",   signed="2024-01-15")

# BFS 遍历 - 从任意节点出发在图中跳转
neighbors = graph.get_neighbors("acme_corp", hops=2)

# 时间点快照 - 图在任意过去日期时的样子
snapshot  = graph.state_at("2024-01-01")

# AgentContext - 面向智能体记忆工作流的高层 API
vs  = VectorStore(backend="faiss")
ctx = AgentContext(vector_store=vs, knowledge_graph=graph)
ctx.store("Alice approved the Acme renewal in Q1 2024", conversation_id="conv_001")
retrieved = ctx.retrieve("who approved the Acme contract?")
```

**为什么用图而不是嵌入:** 图遍历能找到嵌入遗漏的关联(与某份合同相隔 3 跳的人);每个节点都携带溯源,因此你总能问*"这是从哪来的?"*;冲突在污染知识库之前就被标记;时间点快照让你无需重新处理就能回放历史。

<a id="recipe-audit-trail-for-a-regulated-decision"></a>
## 实践配方:受监管决策的审计轨迹

基于同一个上下文图的一种模式:记录带因果链接的决策链,为每个实体附加溯源,并导出可直接提交监管机构的审计轨迹。

```python
from semantica.context import ContextGraph
from semantica.provenance import ProvenanceManager
from semantica.export import RDFExporter

graph = ContextGraph(advanced_analytics=True)
prov  = ProvenanceManager(storage_path="./audit.db")

# 记录决策链
d1 = graph.record_decision(
    category="drug_interaction_check", scenario="患者 P-4821:华法林 + 胺碘酮联合处方",
    reasoning="胺碘酮会增强华法林的抗凝作用", outcome="flag_for_review", confidence=0.91,
)
d2 = graph.record_decision(
    category="dosage_adjustment", scenario="P-4821 的 INR 监测方案",
    reasoning="依据相互作用严重程度减少华法林剂量;5 天后复查 INR", outcome="dose_reduced_30pct", confidence=0.87,
)
# relationship_type 必须是 CAUSED、INFLUENCED 或 PRECEDENT_FOR 之一
graph.add_causal_relationship(d1, d2, relationship_type="CAUSED")

# 追踪每个实体的溯源
prov.track_entity("patient_P4821", source="ehr/medication_orders_2024.json",
                  metadata={"extractor": "NamedEntityRecognizer"})

# 导出 W3C PROV-O 以提交给监管机构 - to_kg_dict() 是官方适配器,
# 会输出 RDFExporter 所期望的 {"entities": [...], "relationships": [...]} /
# source_id 结构,因此无需手动做字段映射
kg = graph.to_kg_dict()
RDFExporter().export(kg, "audit_trail.ttl", format="turtle")
```

<summary><b><code>semantica.semantic_extract</code></b>:NER、关系、事件、三元组</summary>
<a id="semanticasemantic_extract-ner-relations-events-triplets"></a>

```python
from semantica.semantic_extract import (
    NamedEntityRecognizer,
    RelationExtractor,
    EventDetector,
    TripletExtractor,
)

text = """
Anthropic CEO Dario Amodei announced a $7.3B Series E funding round in partnership
with Google and Spark Capital, valuing the company at $61.5B as of Q4 2024.
"""

# 带置信度阈值的命名实体识别
ner = NamedEntityRecognizer(confidence_threshold=0.7)

# → [Entity(name="Dario Amodei", type="PERSON"), Entity(name="Anthropic", type="ORG"),
#    Entity(name="Google", type="ORG"), Entity(name="$7.3B", type="MONEY"), ...]

# 关系抽取 - 支持双向
rel_extractor = RelationExtractor(confidence_threshold=0.6, bidirectional=True)
relations = rel_extractor.extract_relations(text, entities=entities)
# → [Relation(subject="Dario Amodei", predicate="ceo_of", object="Anthropic"),
#    Relation(subject="Anthropic", predicate="raised", object="$7.3B Series E"), ...]

# 带时间处理的事件检测
events = EventDetector(extract_participants=True, extract_time=True).detect_events(text)
# → [Event(type="FUNDING", participants=["Anthropic","Google","Spark Capital"],
#          amount="$7.3B", date="Q4 2024")]

# 带可选溯源元数据的 RDF 三元组
triplets = TripletExtractor(include_temporal=True, include_provenance=True).extract_triplets(text)
# → [("Anthropic", "valuation", "$61.5B"), ("Dario Amodei", "is_ceo_of", "Anthropic"), ...]
```

<summary><b><code>semantica.reasoning</code></b>:前向链、Rete、Datalog、SPARQL</summary>
<a id="semanticareasoning-forward-chaining-rete-datalog-sparql"></a>

运行可解释的基于规则的推理,而不是黑盒。

```python
from semantica.reasoning import ReteEngine, Rule, Fact, RuleType

rete = ReteEngine()
rete.build_network([
    Rule(
        rule_id="aml_flag",
        name="标记高风险交易",
        conditions=[
            {"field": "amount",  "operator": ">",  "value": 10_000},
            {"field": "country", "operator": "in", "value": ["IR", "KP", "SY"]},
        ],
        conclusion="flag_for_compliance_review",
        rule_type=RuleType.IMPLICATION,
    ),
    Rule(
        rule_id="velocity_check",
        name="标记快速连续转账",
        conditions=[
            {"field": "transfers_in_1h", "operator": ">", "value": 5},
            {"field": "total_amount",    "operator": ">", "value": 50_000},
        ],
        conclusion="flag_velocity_breach",
        rule_type=RuleType.IMPLICATION,
    ),
])

rete.add_fact(Fact("tx_001", "transaction", [{"amount": 15_000, "country": "IR"}]))
flagged = rete.match_patterns()
# → [{"rule": "aml_flag", "matched_facts": ["tx_001"], "conclusion": "flag_for_compliance_review"}]
```

> **当前限制:** 在本版本中,`ReteEngine` 的 alpha 节点条件匹配器刻意保持简单 —— 在把 `match_patterns()` 的输出接入生产合规闸门之前,请先针对你实际的规则集进行验证;更具选择性的条件求值已在路线图中。

```python
# 递归 Datalog - 用接近自然语言的方式做图查询
from semantica.reasoning import DatalogReasoner

engine = DatalogReasoner()
engine.add_fact("parent(tom, bob)")
engine.add_fact("parent(bob, ann)")
engine.add_fact("parent(ann, pat)")
engine.add_rule("ancestor(X, Y) :- parent(X, Y).")
engine.add_rule("ancestor(X, Z) :- parent(X, Y), ancestor(Y, Z).")
ancestors = engine.query("ancestor(tom, ?X)")
# → [{"X": "bob"}, {"X": "ann"}, {"X": "pat"}]
```

```python
# 可解释推理 - 追踪路径,而不仅仅是答案
from semantica.reasoning import ExplanationGenerator, Reasoner

reasoner = Reasoner()
reasoner.add_fact("parent(tom, bob)")
reasoner.add_rule("ancestor(X, Y) :- parent(X, Y)")
result = reasoner.forward_chain()

explainer = ExplanationGenerator()
explanation = explainer.generate_explanation(result)
# → Explanation(conclusion="...", steps=[ReasoningStep(...)], justification=Justification(...))
```

<summary><b><code>semantica.conflicts</code></b>:冲突检测与解决</summary>
<a id="semanticaconflicts-conflict-detection--resolution"></a>

在多来源的冲突事实污染你的知识库之前检测并解决它们。

```python
from semantica.conflicts import ConflictDetector, ConflictResolver, SourceTracker

entities_from_source_a = [
    {"id": "alice_chen", "role": "CTO",   "salary": 250_000, "start_date": "2019-03-01"},
]
entities_from_source_b = [
    {"id": "alice_chen", "role": "VP Eng", "salary": 275_000, "start_date": "2019-03-01"},
]

# 检测所有冲突类型:值、类型、关系、时间、逻辑
detector   = ConflictDetector()
conflicts  = detector.detect_conflicts(entities_from_source_a + entities_from_source_b)
# → [Conflict(entity="alice_chen", field="role",   values=["CTO","VP Eng"], severity="HIGH"),
#    Conflict(entity="alice_chen", field="salary",  values=[250000,275000],   severity="MEDIUM")]

# 使用多种策略解决
resolver = ConflictResolver()
resolved = resolver.resolve_conflicts(conflicts, strategy="credibility_weighted")  # 按来源可信度加权
resolved = resolver.resolve_conflicts(conflicts, strategy="most_recent")          # 优先取最新
resolved = resolver.resolve_conflicts(conflicts, strategy="voting")               # 多数胜出

# 长期追踪来源可信度
```

<summary><b><code>semantica.pipeline</code></b>:管线 DSL</summary>
<a id="semanticapipeline-pipeline-dsl"></a>

把接入、抽取和图构建组合成声明式、并行的管线。

```python
from semantica.pipeline import PipelineBuilder, ExecutionEngine

builder = PipelineBuilder()

# add_step() 返回创建的 PipelineStep,而不是 builder,所以它们不能链式调用
builder.add_step("ingest",      step_type="ingest",           source="./contracts/", recursive=True)
builder.add_step("extract",     step_type="ner_extract")
builder.add_step("relations",   step_type="relation_extract")
builder.add_step("build_kg",    step_type="kg_build",         merge_entities=True)
builder.add_step("deduplicate", step_type="deduplicate",      threshold=0.75)
builder.add_step("export",      step_type="export",           format="turtle", output="kg.ttl")

# connect_steps() 和 set_parallelism() 返回 builder,所以它们可以链式调用
pipeline = (
    builder
    .connect_steps("ingest",      "extract")
    .connect_steps("extract",     "relations")
    .connect_steps("relations",   "build_kg")
    .connect_steps("build_kg",    "deduplicate")
    .connect_steps("deduplicate", "export")
    .set_parallelism(4)
    .build(name="contracts_pipeline")
)

engine   = ExecutionEngine()
result   = engine.execute_pipeline(pipeline)
status   = engine.get_pipeline_status(pipeline.name)
progress = engine.get_progress(pipeline.name)
```

<summary><b>时间智能</b>:双时态图与时间旅行</summary>
<a id="temporal-intelligence-bi-temporal-graphs--time-travel"></a>

追踪事实*在现实世界中*何时为真与何时被*记录*,并可沿任一时间轴查询。

```python
from semantica.context import ContextGraph
from semantica.kg import (
    BiTemporalFact,
    TemporalGraphQuery,
    TemporalNormalizer,
)
from datetime import datetime

graph = ContextGraph(advanced_analytics=True)
graph.add_node("alice_chen", "Person",       role="VP Engineering")
graph.add_node("acme_corp",  "Organization", valuation=1_200_000_000)

# 带时间范围的边 - valid_from/valid_until 定义了它何时成立
graph.add_edge(
    "alice_chen", "acme_corp", edge_type="works_for",
    valid_from="2024-03-01T00:00:00", valid_until="2025-01-01T00:00:00",
)

# 时间点快照 - 无需重新处理即可回放历史
snapshot_2023 = graph.state_at("2023-06-01")
snapshot_2024 = graph.state_at("2024-01-01")

# 双时态事实 - valid_time 是在现实世界中为真的时间;
# recorded_at 是你获知它的时间
fact = BiTemporalFact(
    valid_from=datetime(2024, 3, 1),
    valid_until=datetime(2025, 1, 1),
    recorded_at=datetime(2024, 3, 5),
)

# 查询在某个时间窗口内有效的事实 - to_kg_dict() 是官方适配器,
# 会输出带 source_id/target_id 键的 {"entities", "relationships"},
# 正是 query_time_range() 所期望的结构(无需手动映射)
kg = graph.to_kg_dict()

tq = TemporalGraphQuery()
facts_in_window = tq.query_time_range(
    kg, query="valid_facts", start_time="2024-01-01", end_time="2024-12-31"
)

# 规范化自然语言时间表达 - 返回 (start, end) 范围
norm = TemporalNormalizer(reference_date=datetime(2026, 1, 1))
start, end = norm.normalize("last quarter")
```

<summary><b>端到端 GraphRAG 管线</b></summary>

```python
from semantica.ingest import FileIngestor
from semantica.split import TextSplitter
from semantica.semantic_extract import NamedEntityRecognizer, RelationExtractor
from semantica.kg import GraphBuilder
from semantica.vector_store import VectorStore, HybridSearch
from semantica.context import AgentContext

# 1. 接入
docs = FileIngestor().ingest_directory("./docs/", recursive=True)

# 2. 实体感知分块 - 绝不把实体拆到分块边界两侧
splitter = TextSplitter(method="entity_aware", chunk_size=1000)
chunks   = [splitter.split(doc.text) for doc in docs]

# 3. 抽取实体和关系
ner      = NamedEntityRecognizer(confidence_threshold=0.7)
rel_ext  = RelationExtractor(confidence_threshold=0.6)
entities = [ner.extract_entities(chunk.text) for chunk_group in chunks for chunk in chunk_group]

# 4. 构建知识图谱
kg = GraphBuilder(merge_entities=True, enable_temporal=True).build(docs)

# 5. 混合检索
vs  = VectorStore(backend="inmemory")
ctx = AgentContext(vector_store=vs, knowledge_graph=kg)
ctx.store("Alice approved the Acme renewal in Q1 2024", conversation_id="c1")

results = HybridSearch(vector_store=vs).search("who approved the renewal?")
```

```python
            {"field": "amount",  "operator": ">",  "value": 10_000},
            {"field": "country", "operator": "in", "value": ["IR", "KP", "SY", "CU"]},

        conclusion="flag_for_compliance_review",
        rule_type=RuleType.IMPLICATION,
    ),
])

# 对一批传入的交易运行规则,而不仅仅是一笔
for tx in [
    Fact("tx_101", "transaction", [{"amount": 25_000, "country": "IR"}]),
    Fact("tx_102", "transaction", [{"amount": 4_500,  "country": "DE"}]),
    Fact("tx_103", "transaction", [{"amount": 60_000, "country": "KP"}]),

    rete.add_fact(tx)

flagged = rete.match_patterns()
```

```bash
python -m semantica.mcp_server
```

<a id="rest-api"></a>
### REST API

```bash
# 启动后端
python -m semantica.server   # 端口 8000

# 通过 REST 提取实体与关系
curl -X POST http://localhost:8000/api/enrich/extract \
  -H "Content-Type: application/json" \
  -d '{"text": "Apple CEO Tim Cook announced record earnings."}'

# 列出已记录的决策
curl "http://localhost:8000/api/decisions?category=vendor_selection"

# 查询知识图谱
curl "http://localhost:8000/api/graph/node/acme_corp/neighbors?depth=2"
```

**REST 端点涵盖:** `enrich`(抽取)· `graph` · `decisions` · `reasoning` · `provenance` · `ontology` · `embeddings` · `search` · `export` · `pipeline` · `temporal` · `deduplication`

### 插件包

**领域技能:** `extract` · `ingest` · `query` · `ontology` · `validate` · `deduplicate` · `embed` · `reason` · `decision` · `causal` · `temporal` · `provenance` · `policy` · `explain` · `export` · `change` · `visualize`

**专用智能体:** `kg-assistant` · `decision-advisor` · `explainability`

适用于 Claude Code、Cursor、Codex、pi、Windsurf、Cline、Continue、VS Code 和 OpenClaw 的插件包位于 [`plugins/`](plugins/)。

<a id="knowledge-explorer"></a>
## Knowledge Explorer

一个基于浏览器的图工作台。可以平移和缩放实时图、拖动时间线、查看每个决策的因果链、解决重复项,并以可视化方式编写你的本体。基于 React 19 + Sigma.js 构建。

| 工作区 | 你可以做什么 |
| --- | --- |
| **知识图谱** | 实时 Sigma.js 画布,ForceAtlas2 布局、Ego 模式、语义距离热力图 |
| **时间线** | 拖动浏览时间事件,观看图的演化 |
| **决策** | 浏览每个已记录决策背后的因果链 |
| **注册表** | 图上每一次变更的实时审计日志 |
| **实体消解** | 审阅并合并重复项 |
| **本体中心** | SHACL Studio、可视化编辑器、跨本体对齐、SKOS 浏览器 |
| **血缘** | 任意实体的 W3C PROV-O 溯源可视化 |

最快的启动方式(无需 Node.js):

```bash
pip install "semantica[explorer]"
semantica-explorer --graph my_graph.json
# 仪表盘将在 http://127.0.0.1:8000 打开
```

贡献者 / 开发服务器的搭建方式:**[explorer/README.md:本地搭建指南](explorer/README.md)**

CLI 暴露的是已加载的 `ContextGraph`。若还想浏览和编辑已有的 `AgentMemory`,请以编程方式创建 ASGI 应用,同时传入这两个运行中的对象:

```python
from semantica.context import AgentMemory, ContextGraph
from semantica.explorer.app import create_app
from semantica.explorer.session import GraphSession

graph = ContextGraph()
memory = AgentMemory()
app = create_app(session=GraphSession(graph), agent_memory=memory)
```

只有在提供了 `agent_memory` 时才会显示 Memories 工作区。Apply 会更新你所提供的运行时对象;它不会增加磁盘持久化。

<a id="whats-new-in-v070"></a>
## v0.7.0 新特性

**核心安装体积缩小了 4 倍。** 直接依赖从 44 个减少到 22 个 —— 重量级的 ML/NLP、可视化、文档解析和接入库(`torch`、`spacy`、`sentence-transformers`、`matplotlib`、`faiss-cpu`、`python-docx` 等)被移到了细粒度的可选扩展中。`pip install "semantica[all]"` 可保持原先完整打包的行为。这也是第一个要求 **Python 3.10+** 的版本(不再支持 3.8/3.9;尚不支持 3.14),并附带已提交的 `uv.lock`,以便开发环境可复现地安装:

- **层级社区 GraphRAG**:多层级 Louvain/Leiden 社区发现、由 LLM 总结的社区报告,以及全局 Map-Reduce + DRIFT 混合搜索(`ContextRetriever(mode="global"|"drift"|"hybrid")`,新增 `semantica kg global`/`semantica kg drift` CLI 命令)—— 新增 193 个测试
- **六个新的数据连接器**:BigQuery、Amazon Redshift、Power BI、Apache Airflow,以及按行分隔的 JSON(`.jsonl`/`.ndjson`)接入
- **模式引导的抽取**:`SchemaValidator` 依据领域本体检查抽取输出,`bootstrap_schema` 从抽取的数据中归纳出本体草稿,供人工确认
- **来源感知的真值维护与信任分层**:新的 `TruthMaintenanceSession` 为非递归规则追踪事实的支持与撤回,`ContextRetriever` 可按活跃/受支持的事实过滤检索到的上下文,图中的事实现在会基于佐证获得信任层级(quarantine/bronze/silver/gold)
- **持久化抽取缓存**:`ExtractionCache` 新增可插拔的 `CacheBackend`,包括新的 SQLite 后端,使缓存的 LLM 抽取结果在进程重启后依然保留
- **MCP 新增语义检索工具**(`store_document`/`retrieve_context`/`update_document`/`remove_document`),并修复了溯源、因果链序列化和导出处理器中的 6 个 bug
- **`SPARQLReasoner.execute_query` 现在会真正执行查询**,针对已配置的三元组存储或内存中的 `rdflib.Graph`,而不是之前的空操作
- **安全性**:移除了 `crewai` 扩展以关闭未修复的 `chromadb`/`json-repair` CVE,修复了 Neptune 凭据日志泄漏,并修正了 pip-audit 中 CVE 别名匹配的缺口

**破坏性变更**:`Entity.confidence` 现在是 `Optional[float]`(之前是 `float = 1.0`),这样未测量的置信度就不再与满分无法区分;`PolicyEngine.check_compliance` 对于无法求值的规则现在会抛出 `ProcessingError`(之前返回 `False`);`dev` 扩展已移除,改用 PEP 735 依赖组;`semantica[crewai]` 不再自动安装 `crewai`。

同时修复了 40 多个正确性 bug(内存向量 ID 复用导致活跃向量损坏、FAISS/Qdrant/Milvus 向量库的缺陷、Explorer 时间拖动条和本体链接的 bug、CLI 命令调用不存在的 API 等),以及站点范围内的大量文档更正。

→ [完整发布说明](RELEASE_NOTES.md) · [变更日志](CHANGELOG.md)

<a id="installation"></a>
## 安装

```bash
pip install semantica             # 轻量核心(22 个必需依赖)
pip install "semantica[all]"      # 完整打包行为,包含所有扩展
```

> **注意:** 重量级的机器学习、NLP、可视化和文档依赖都放在可选扩展中,以保持核心安装轻量且快速。如果你想要之前的完整打包安装,请使用 `pip install "semantica[all]"`。

```bash
# 细粒度扩展
pip install "semantica[documents]"          # 文档解析(docx、openpyxl、lxml、beautifulsoup4)
pip install "semantica[embeddings-local]"   # 本地嵌入(sentence-transformers、fastembed、onnxruntime)
pip install "semantica[models-huggingface]" # HuggingFace 模型(transformers、torch)
pip install "semantica[nlp-spacy]"          # spaCy NLP 管线(spacy)
pip install "semantica[nlp-langdetect]"     # 用于 LanguageDetector 的语言检测(langdetect)
pip install "semantica[viz]"                # 可视化(matplotlib、seaborn、plotly、pyvis、graphviz)
pip install "semantica[media]"              # 音频与计算机视觉(librosa、opencv-python)
pip install "semantica[graph-embeddings]"   # 知识图谱嵌入(gensim / Node2Vec)
pip install "semantica[ingest-git]"         # Git 仓库接入器(GitPython)
pip install "semantica[vectorstore-faiss]"  # FAISS 向量库
pip install "semantica[vectorstore-all]"    # 所有向量库(Qdrant、Pinecone、Weaviate、FAISS、PgVector、SQLite)
pip install "semantica[agno]"               # Agno 多智能体集成
pip install "crewai>=0.80.0"                # CrewAI 集成(没有 semantica 扩展 —— 见 integrations/crewai/README.md)
pip install "semantica[langchain]"          # LangChain / LangGraph 集成
pip install "semantica[llm-all]"            # 所有 LLM 供应商客户端
pip install "semantica[graph-neo4j]"        # Neo4j 图存储(LPG)
pip install "semantica[graph-falkordb]"     # FalkorDB 图存储(LPG)
pip install "semantica[graph-apache-age]"   # Apache AGE 图存储(LPG)
pip install "semantica[graph-amazon-neptune]" # AWS Neptune 图存储(LPG)
pip install "semantica[tripletstore-oxigraph]" # 内嵌的内存/磁盘 RDF 存储
# RDF 三元组存储(Blazegraph、Apache Jena、Eclipse RDF4J)无需额外扩展:
# semantica.triplet_store 通过 HTTP 使用 SPARQL,依赖的是核心的 `requests`
pip install "semantica[db-snowflake]"       # Snowflake
pip install "semantica[db-databricks]"      # Databricks(SDK + SQL 连接器)
pip install "semantica[ingest-sap]"         # SAP OData
pip install "semantica[ingest-servicenow]"  # ServiceNow Table API
pip install "semantica[ingest-parquet]"     # Parquet / PyArrow
pip install "semantica[ingest-arrow]"       # Apache Arrow、Feather、IPC
pip install "semantica[watch]"              # 目录文件监视器
pip install "semantica[explorer]"           # Knowledge Explorer 仪表盘
```

生产部署请使用 Docker 或 Kubernetes,而不是本地 `pip install`。设置 `SEMANTICA_API_KEY`,配置持久化的 LPG 图存储(Neo4j / FalkorDB / Apache AGE / AWS Neptune)和/或 RDF 三元组存储(Blazegraph / Apache Jena / Eclipse RDF4J),并将向量库指向托管后端(Qdrant / Pinecone)。完整的部署拓扑见 [ARCHITECTURE.md](ARCHITECTURE.md)。

```bash
# 从源码安装
git clone https://github.com/semantica-agi/semantica.git
cd semantica && pip install -e . --group dev && pytest tests/
```

### CI 与部署

```yaml
- uses: semantica-agi/semantica/.github/actions/setup-semantica@main
```

适用于 AWS、GCP、Azure、Fly.io、Railway、Render、Kubernetes 和 Helm 的现成部署配置位于 [deploy/](deploy/)。
